# TrimWise 调研与决策（2026-10-20）

## 1. 这个 idea 成立吗

**成立，但要做“决策”，不要做“记账”。**

- 记账赛道已经很挤：随手记、鲨鱼、钱迹、iCost、一木都在做“记录 + 报表”。它们的 AI 能力用在录入环节（语音、截图识别），没有一家做“该砍哪、砍多少、砍了会不会影响生活”的诊断。
- 需求有真实信号：已经有人把微信账单丢给 DeepSeek 分析（什么值得买等社区帖子），也有人自己写脚本生成月报。但通用聊天机器人给的建议很泛（“控制购物类，可省 20–30%”），算不准，也落不了地。
- 海外最接近的是 Rocket Money：帮用户找订阅、代为取消、砍账单，付费模式成立。Copilot / Monarch / YNAB 每年约 99 美元，主打“看清”和“预算方法论”。
- **风险**：一是记账/理财类 App 留存普遍差（健康类 App 100 天内约 70% 停用，财务类更低）；二是“AI 账单分析”小程序跟进很快。
- **对策**：
  - 产品的“一次性价值”（年度体检 + 可砍清单）要足够强，导入一次就值。
  - 用“每月消费卡 + 月度复盘”做轻量的复访，不靠天天打卡。
  - 差异化放在：规则可追溯、AI 不编数字、数据不出浏览器。

### 竞品一览

| 产品 | 定位 | 价格 | 会不会告诉你“砍哪” |
|---|---|---|---|

## 2. 形态：网站（PWA），不是小程序，也不是 App

| | 网站 / PWA | 微信小程序 | 原生 App |
|---|---|---|---|
| 导入账单 | **最顺**：在电脑上下载邮箱里的 zip，拖进页面；在浏览器里直接解密、解析 | **很难**：`wx.chooseMessageFile` 只能从聊天记录里选文件。用户要先下载 zip、自己解压，再转发到“文件传输助手” | 可以用“文件”App 和分享扩展，体验不错 |
| 大表格、年度对比 | 适合大屏 | 屏幕太小 | 一般 |
| 本地优先（流水不上传） | 可以：IndexedDB + 浏览器内解析 | 本地存储上限 10MB，6 年流水接近上限 | 可以 |
| 提醒 | 日历订阅（已做）、邮件、Web Push | 一次性订阅消息，每月要重新授权 | 推送 |
| 上线门槛 | ICP 备案（waywise.tech 已有） | 小程序备案 + 类目；“工具-记账”不需要金融资质 | 软著、算法登记、上架审核，成本最高 |
| 与现有产品一致性 | readwise / investwise 都是网站，部署方式一样 | waywise 家长端是小程序 | — |

**结论**：

- **第一期**：网站 + PWA（可以添加到手机桌面）。
- **第二期**：等验证了留存，再考虑做一个轻量的小程序，只承载“本月消费卡还剩多少”“冷静期到期提醒”和分享。数据仍以网页端为主。
- **原生 App**：暂不做。

这和 readwise / investwise 的形态一致，但在架构上和它们有一个关键不同：**服务器看不到流水**。不登录时数据只在本机；登录后数据在浏览器里加密再同步，服务器只存密文。

## 3. 合规要点（上线前要处理）

- **个人信息保护法**：交易流水属于“金融账户”相关信息，大概率按**敏感个人信息**处理（第 28 条），需要**单独同意**（第 29 条）。
  - 已做：流水只在浏览器里处理，服务器不接收、不保存。
  - 已做：第一次用 AI 前弹出单独同意，写明发送什么、发给谁；每次发送前都能查看完整内容；可以关掉“包含商户名”。
- **把汇总发给 DeepSeek** 属于向第三方提供。已做脱敏：不发逐笔流水、账户、订单号。
- **生成式 AI 登记**：面向公众提供、调用已备案大模型 API 的服务，需要到属地网信办做登记，并在页面显著位置公示所用模型和备案号。
  - 已做：页面底部有公示位，内容由 `.env` 里的 `MODEL_DISCLOSURE` 配置。
  - **待办**：按登记结果填写公示内容。
- **不提供投资建议**：提示词禁止推荐具体的理财产品、基金、股票；自由基金的收益率只是用户自己填的假设。

## 4. 关键设计决策

1. **规则算数，AI 说话。** 可省金额全部由 `static/js/analyze.js` 的确定性规则算出，并能追溯到具体交易。AI 只做四件事：每周复盘（从规则算出的候选里挑目标）、月度复盘、问答、把未分类的商户归类。
2. **账号可选，同步端到端加密**（2026-10-20 改）。最初的方案是没有账号、纯本地。后来决定加账号，因为要做“每周一主动发复盘和指导”：没有账号就没法找到用户，也没法在用户不打开网页时生成复盘。
   - 不登录：打开就能用全部本地分析，数据只在本机。
   - 登录：流水用密码派生的密钥在浏览器里加密后同步，服务器解不开；忘了密码只能重设，云端密文清空。
   - 每周复盘需要的汇总（按周、按分类，和发给 AI 的一样）在用户同意并开启每周邮件后才上传，关掉就删除。
   - 内测期间凭邀请码注册，AI 功能只对登录用户开放，按用户限次。
3. **四象限。** 固定刚性（不砍，只优化单价）、固定弹性（逐个审计）、高频弹性（进每月消费卡）、偶发大额（年初定预算）。归属可以在「数据」页改。
4. **可砍清单的六类规则：**
   - 订阅黑洞：按月或按年固定扣款，最近还在扣。
   - 无感支出：单笔中位数 ≤ ¥200，每月 ≥ 8 次。
   - 冲动大额：≥ ¥2000，标出深夜下单、情绪词、大促；要人工复盘“值不值”。
   - 分类膨胀：同比 +20% 且多花 ≥ ¥3000。
   - 偶发大额：超出往年中位数。
   - 单价审计：固定弹性里每年 ≥ ¥1 万的项目。

   合计可省时，同一笔交易只算一次，取最大的节省比例。
5. **消费卡超支最多扣下月额度的 30%。** 不设上限的话，一次超支会越滚越大，额度被扣到 0，人就放弃了。
6. **数据不足一年时按月份折算，不做同比。** 很多人只有几个月的微信账单，页面上会提示“导入更长时间会更准”。
7. **多来源重叠检测。** 随手记和微信、支付宝里，同一笔钱经常会出现两次。导入时，会在两边时间重叠的范围内比对“同一天、同金额”，重叠比例高就提示用户。
8. **每周目标必须能自动判定。** 规则先算出候选（消费卡周额度、无感支出的周上限 / 次数上限、不买大件、取消订阅等一次性动作），AI 只从候选里挑 3 个、写理由，服务器校验 ID。这样“下周看结果”不依赖用户自觉打卡，只要导入账单就知道完成了没有。
9. **每周一的邮件分两种。** 上周的账单已经导入了，就发复盘和这周的目标；还没导入，就发提醒，列出上周定的目标，请用户花 3 分钟导入。每周的数据要靠用户手动导出，这是这个产品最大的摩擦，见第 5 节。

## 5. 还没核实的事

- **每周导入的摩擦有多大**：微信、支付宝都没有开放个人账单 API，每周的数据只能靠用户自己导出（微信下载账单要等邮件）。内测时重点看：收到提醒邮件后，有多少人真的会去导入。如果太低，可以考虑：每周只要一个数字（消费卡余额）的手动打卡；或者两周一次。
- 随手记网页版导出是否需要会员，以及当前版本的准确列名。解析器是按列名模糊匹配的，**需要拿一份真实导出文件验证**。
- 微信账单最新的导出格式（CSV 还是 xlsx）。两种都支持，但没有用真实文件测过。
- 小程序长期订阅消息现在对哪些类目开放。这一条影响第二期小程序的提醒能力。
